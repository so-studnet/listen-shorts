# 準備と確かめ方（So 向け）

最終更新：2026-11-22（M8）

PC（Windows）にもスマホにも、何もインストールする必要はありません。ブラウザだけで進めます。

---

## 1. GitHub：既定のブランチを `main` にする（最初の1回だけ）

Vercel は、リポジトリの既定のブランチを「本番」として読み込みます。最初に Claude の作業ブランチが push されたため、いまは作業ブランチが既定になっています。これを `main` に切り替えます（`main` は Claude が作成済み）。

1. PC のブラウザで https://github.com/so-studnet/listen-shorts を開く
2. 上のタブの右端の **Settings**（歯車）を押す
3. 左のメニューの **General** が開いた状態で、「Default branch」の欄を探す（少し下にスクロール）
4. 枠の右にある **⇄**（左右の矢印のボタン）を押す
5. 出てきた一覧で **main** を選び、**Update** を押す
6. 確認の画面で **I understand, update the default branch.** を押す
7. 「Default branch」の欄が `main` になっていれば完了

### 以後の取り込み方（M2 以降）

マイルストーンが終わったら、Claude が PR（作業ブランチ → `main`）を作ることがあります。そのときは、PR のリンクを開いて、下のほうの緑のボタン **Merge pull request** → **Confirm merge** を押します。横に出る **Delete branch** は押さないでください（Claude が同じブランチで続きを作ります）。

## 2. Vercel：プロジェクトを作る（最初の1回だけ）

1. PC のブラウザで https://vercel.com を開き、右上の **Log In** → **Continue with GitHub** でログインする
2. 左上のチーム名が **so** になっていることを確かめる
3. 右上の **Add New…** → **Project** を押す
4. 「Import Git Repository」の一覧で、**listen-shorts** の横の **Import** を押す
   - 一覧に出てこないとき：一覧の下の **Adjust GitHub App Permissions →** を押し、開いた GitHub の画面の「Repository access」で `listen-shorts` を選んで **Save** を押す。Vercel の画面に戻ると出てきます
5. 「Configure Project」の画面で、次を確かめる（変えるところはありません）
   - **Application Preset**：`Next.js`（`Other` になっていたら、右の一覧から `Next.js` を選ぶ）
   - **Root Directory**：`./`
   - **Environment Variables**：何も入れない（M8 まで不要）
6. **Deploy** を押す。1〜2分で紙吹雪の画面になれば成功
7. **Continue to Dashboard** を押す。**Domains** に出ている `listen-shorts-〜.vercel.app` が本番の URL です。この URL を Claude に教えてください

以後は、Claude が作業ブランチに push するたびに **プレビュー**（試し版）が自動で作られます。プロジェクトの画面の **Deployments** タブで、いちばん上の行（ブランチ名 `claude/dazzling-goodall-tbon1q`）を押し、右上の **Visit** を押すと開けます。

### プレビューの URL を iPhone で開くとき

- プレビューの URL は、Vercel にログインしている人しか開けない設定になっている見込みです（【未確認】）。iPhone の Safari で開いて Vercel のログイン画面が出たら、**Continue with GitHub** でログインしてください。一度ログインすれば、次からはそのまま開けます
- 本番の URL（`listen-shorts-〜.vercel.app`）は、M8 でログインを付けるまで誰でも開ける見込みです（【未確認】）。載っているのは架空の英文のサンプルだけなので問題ありません

## 3. iPhone で1本解いてみる（M1 の確かめ方）

サンプルパックの動画 ID は仮のもの（`SAMPLE00001` など）なので、**サンプルでは「動画が見つかりません」と出て音が出ません**。画面の流れは、「クイズへ進む」を押せばサンプルでも確かめられます。

音を出して試すには、本物のパックを1つ読み込みます。

1. パックを作るチャットに `docs/pack-format.md` の内容を渡し、クリップ1〜2本の小さいパックを作ってもらう
   - M1 では **穴埋め（cloze）の問題だけ** が出ます（聞き分け・並べ替えは M2 から）
2. できた JSON を iPhone でコピーする（チャットのコードブロックの「コピー」ボタン）
3. アプリを開き、右上の **パック** → テキスト欄を長押し → **ペースト** → **読み込む**
   - 「〜を読み込みました」と出れば成功。赤い枠でエラーが出たら、その文をパックを作るチャットに貼れば直してもらえます
4. **← クイズへ** を押す。読み込んだパックのクリップが最初に出ます
5. **▶ タップして再生** → 聞き終わったら **クイズへ進む** → 答える → … → 結果

本物のパックは、その iPhone のブラウザの中にだけ保存されます（GitHub や Vercel には送られません）。

### 確かめて教えてほしいこと

- [ ] 動画がクリップの区間（開始〜終了）だけ再生されて止まるか。止まる位置が早すぎて文の終わりが切れていないか
- [ ] 字幕が出ていないか
- [ ] 「この文を聞き直す」で、その文だけが再生されるか
- [ ] 答えの入力で、勝手に大文字になったり、自動修正されたりしないか
- [ ] 文字やボタンの大きさ、片手での押しやすさ

## 4. iPhone のホーム画面に追加する（M7）

1. iPhone の Safari で本番の URL を開く
2. 画面の下にある **共有ボタン**（□ に ↑ のマーク）を押す
3. 出てきた一覧を上にずらし、**ホーム画面に追加** を押す
4. 名前が「ListenShorts」になっていることを確かめて、右上の **追加** を押す
5. ホーム画面に青いアイコンができる。以後はこのアイコンから開く

### Safari で解いた記録を、ホーム画面のアプリに移す

iPhone では、ホーム画面のアプリと Safari とで保存場所が別になります。Safari で解いた記録や読み込んだパックは、そのままではホーム画面のアプリに出てきません。

1. **Safari で** アプリを開き、**設定** タブ → **⬇️ データを書き出す** を押す
2. 「ダウンロードしますか？」と出たら **ダウンロード** を押す（「ファイル」アプリの「ダウンロード」に保存されます）
3. **ホーム画面のアイコンから** アプリを開き、**設定** タブ → **⬆️ 書き出したファイルから読み込む** を押す
4. 「ブラウズ」→「ダウンロード」の中の `listen-shorts-日付.json` を選ぶ
5. 中身（解答の件数など）を確かめて **置き換える** を押す

## 5. ログインと同期（M8）

データベースの表（名前が `ls_` で始まる5つ）は、Claude が Supabase の接続から作成済みです。作業記録アプリと同じ Supabase プロジェクト（so-studnet's Project）に置いています。So にやってもらうのは次の3つです。

### 5-1. ログインのアカウントを用意する

- **作業記録アプリにログインしているメールアドレスとパスワードがあれば、それがそのまま使えます**（同じプロジェクトなので、アカウントも共通）。この場合は 5-2 へ
- 新しく作るとき：
  1. https://supabase.com/dashboard を開き、**so-studnet's Project** を選ぶ
  2. 左のメニューの **Authentication**（人の形のアイコン）→ **Users**
  3. 右上の **Add user** → **Create new user**
  4. メールアドレスとパスワードを入れ、**Auto Confirm User** にチェックを入れて **Create user**

### 5-2. 新規登録の設定を確かめる

同じプロジェクトにほかのアプリもあるので、誰でもアカウントを作れる設定になっていないかを確かめます。

1. 左のメニューの **Authentication** → **Sign In / Providers**
2. **Allow new users to sign up** がオンかオフかを見る
   - オンなら、誰でもアカウントを作って ListenShorts にログインできてしまいます（ただし、その人には自分の空のデータしか見えません。So のパックや記録は本人しか読めません）
   - ほかのアプリで新規登録を使っていなければ、オフにして **Save changes** を押すのがおすすめです

### 5-3. Vercel に接続情報を入れる

値は Claude が会話で伝えます（どちらも公開してよい値です。Supabase の画面の **Project Settings → API Keys** の **Publishable key** と同じもの）。同じ画面にある **Secret keys**（`sb_secret_...`）は使いません。会話にも貼らないでください。

1. https://vercel.com で **listen-shorts** のプロジェクトを開く
2. 上のタブの **Settings** → 左のメニューの **Environment Variables**
3. 次の2つを1つずつ入れる。**Key** と **Value** を入れ、**Environments** は **Production** と **Preview** にチェックを入れて **Save**
   - Key：`NEXT_PUBLIC_SUPABASE_URL`　Value：`https://〜.supabase.co`
   - Key：`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`　Value：`sb_publishable_〜`
4. 値はビルドのときに埋め込まれるので、作り直しが要る。上のタブの **Deployments** → いちばん上の行の右端の **⋯** → **Redeploy** → **Redeploy**
5. 1〜2分後に本番の URL を開くと、ログイン画面が出る

### 5-4. ログインして、これまでの記録を取り込む

1. ログインすると、「このブラウザに、ログイン前の記録があります。アカウントに取り込みますか？」と出る → **取り込む**
2. iPhone は、Safari とホーム画面のアプリとで別々にログインが要る（保存場所が別のため）。それぞれで **取り込む** を押してよい（同じ記録が二重になることはない）
3. PC のブラウザでも同じアカウントでログインすると、同じ記録・パック・復習が見える

制約：オフラインのときに解いた分は保存されません（画面の上に「オフラインです」と出ます）。

## 困ったとき

| 症状 | 見るところ |
|---|---|
| Vercel の Application Preset が `Other` になる | 手順1（既定のブランチを `main` に）が済んでいるか確かめる。済んでいれば一覧から `Next.js` を選ぶ |
| Deploy が赤くなって失敗した | プロジェクトの **Deployments** → 失敗した行 → **Build Logs** の画面のスクリーンショットを Claude に見せる |
| 「この動画は埋め込みでの再生が許可されていません」 | その動画は使えない。パックを作るチャットに別の動画にしてもらう |
| 「動画が見つかりません」 | 動画 ID の誤りか、動画が削除・非公開。パックの `videoId` を確かめる |
| ログイン画面が出ない | Vercel の環境変数を入れたあと Redeploy したか。値の前後に空白が入っていないか |
| 「同期できませんでした」の帯が消えない | 「読み直す」を押す。だめなら通信状態を確かめ、画面のスクリーンショットを Claude に見せる |
| 画面が古いまま | Safari で再読み込み（アドレスバーの左の更新ボタン）。ホーム画面のアプリは、一度上にスワイプして完全に閉じてから開き直す |
