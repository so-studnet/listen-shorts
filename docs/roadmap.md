# ListenShorts ロードマップ

最終更新：2026-11-22（M3）

## 進め方

「小さく作って、触って、直す」アジャイル型。マイルストーンごとに次の順で進め、毎回「触れる状態」で区切る。

1. ドメインの純粋関数とテストを先に書く
2. 保存先・画面とつなぐ
3. `npm run check`（テスト・lint・型チェック・ビルド）を通す
4. Playwright でスマホ幅（iPhone の大きさ）を操作し、スクリーンショットで確かめる
5. この表の状態を更新して、コミット・push する
6. So に、スクリーンショット・できたこと・自分で決めたこと・未確認のことを報告する。So は Vercel のプレビュー URL を iPhone で開いて触る

### たたき台からの変更【決定】

- **Vercel を M9 から M1 に前倒し**：So は手元で動かさないので、M1 から Vercel のプレビュー URL を iPhone で開いて確かめる。M9 は「本番の仕上げ」にする
- **M1 にパックの貼り付け読み込み（簡易版）を入れる**：サンプルパックの動画 ID は仮のものなので、そのままでは音が出ない。M1 で本物のパックを1つ貼り付けて試せるようにする。行番号つきのエラー表示などの仕上げは M6 のまま
- **M3 にタブバーを入れる**：画面が2つ以上になるのが M3 から（M1・M2 はクイズの画面だけ）

## 公開と非公開について

- M1〜M8 の間、本番 URL（`〜.vercel.app`）は誰でも開ける状態になる見込み
  - 【未確認】Vercel の無料プラン（Hobby）のログイン保護（Vercel Authentication）は、プレビューの URL は守るが、本番の URL は守らない見込み。M1 で設定画面を見て確かめる
  - その間、サーバーに載るのはサンプルパック（架空の英文）だけ。本物のパックは、貼り付けた端末のブラウザの中（localStorage）にしかないので、他人には見えない
- M8 でログイン必須にし、パックと記録は Supabase の RLS で本人しか読めないようにする

## M1 の結果と、確かめ方

- 手順は `docs/setup.md`（PR のマージ、Vercel のプロジェクト作成、iPhone での確かめ方、本物のパックで試す方法）
- リポジトリに `main` がなく作業ブランチが既定になっていたので、So の許可を得て Claude が `main` を作った（M1 の時点の内容）。既定のブランチの切り替えは So が GitHub の設定で行う
- Vercel のプロジェクトは、Claude の側（Vercel の接続）からは権限がなく作れなかった（403）。So に画面で作ってもらう
- 自動テスト（Playwright）は、この開発環境から YouTube に接続できないため、**偽の YouTube プレーヤー**（`e2e/fake-youtube.js`）で行っている。区間の頭への移動・終わりでの停止・聞き直しの回数・保存は確かめた
- 【未確認】本物の YouTube での区間再生（iPhone の Safari、止まる位置のずれ、字幕が出ないか）。So に iPhone で確かめてもらう
- 【未確認】Vercel のプレビュー URL のログイン保護が iPhone でどう見えるか

- So が iPhone の Safari で本番 URL を開けることを確かめた（2026-11-20）。存在しない動画 ID（例の `XXXXXXXXXXX`）では、YouTube がエラー 150（埋め込み禁止と同じ番号）を返した。メッセージを「埋め込みが許可されていないか、動画 ID が誤っています」に直し、再生できないときは再生ボタンを隠した
- 【未確認】本物の動画での区間再生（iPhone）

### M1 で自分で決めたこと

- パックの読み込み画面は `/packs`（M3 でタブバーの「設定」の中に移す）
- 視聴中、再生を始めたら「クイズへ進む」をいつでも押せる（全体を聞き終える前でも進める）。動画が再生できないときも進める
- M1 では聞き直しにライフを使わない（ライフは M2）
- 聞き分け・並べ替えの問題は、M1 では飛ばす（M2 で出す）
- クリップは、読み込んだパック（新しい順）→ サンプル の順に1本ずつ出す。「次のクリップ」で次へ、最後まで行ったら最初に戻る（並び順と絞り込みは M3）

## M2 の結果

- 聞き分け（選択肢はシャッフル）・並べ替え（カードは元の順にならないようにシャッフル。並べたカードをタップすると戻る、「並べ直す」で全部戻る）
- ライフ（文の聞き直し1・全体の見直し2）、ヒント（穴埋めのみ）、得点・コンボ・スピードボーナス、結果画面の内訳（問題の得点・残りライフの得点・最大コンボ）
- コンボはクリップをまたいで続き、保存する。再挑戦（一度解いたクリップ）は XP が半分
- 画面のテスト（偽の YouTube プレーヤー）で、3形式が混ざったクリップ・ライフの消費と上限・ヒント・コンボ・スピードボーナス・再挑戦の半分を確かめた

### M2 で自分で決めたこと

- 解答後（判定の画面）と結果画面での聞き直しは**無料**（ライフを使わない）。ライフは「答える前に聞き直す」ことの代償なので
- 聞き直しの再生中は次の聞き直しを押せない。残り時間（⚡）は再生中に止まり、⏸ を出す
- 選択肢・カードの混ぜ方は、クイズの開始時に乱数の種を1つ決めて計算する（テストで固定できるように）
- ヒントを使ったら「ヒント」ボタンを消し、ヒントの文字（例：`T______ a`）を入力欄の上に出す

## M3 の結果

- タブバー（フィード／復習／記録／設定）。パックの読み込みは「設定」に移した。「復習」は M4 まで案内だけ
- フィード：縦スワイプ（scroll-snap）、まだ解いていないクリップが先、絞り込み（パック・アクセント・難易度。保存する）、レベルの帯

- 画面のテストで、スワイプ・クイズ中のスワイプの停止・ご褒美の表示・絞り込み・記録タブを確かめた
- 【未確認】iPhone の Safari で、scroll-snap のスワイプが気持ちよく止まるか。クイズ中のスワイプの停止が効くか
- 【未確認】タブを移って戻ったとき：Next.js は前の画面の状態を残すので、解いている途中のクイズは残る見込み。プレーヤーは作り直される
