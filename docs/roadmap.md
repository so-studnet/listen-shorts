# ListenShorts ロードマップ

最終更新：2026-11-22（M9）

## 進め方

「小さく作って、触って、直す」アジャイル型。マイルストーンごとに次の順で進め、毎回「触れる状態」で区切る。

1. ドメインの純粋関数とテストを先に書く
2. 保存先・画面とつなぐ
3. `npm run check`（テスト・lint・型チェック・ビルド）を通す
4. Playwright でスマホ幅（iPhone の大きさ）を操作し、スクリーンショットで確かめる
5. この表の状態を更新して、コミット・push する
6. So に、スクリーンショット・できたこと・自分で決めたこと・未確認のことを報告する。So は Vercel のプレビュー URL を iPhone で開いて触る

### たたき台からの変更【決定】

- **Vercel を M9 から M1 に前倒し**：So は手元で動かさないので、M1 から Vercel のプレビュー URL を iPhone で開いて確かめる。M9 は「本番の仕上げ」にする
- **M1 にパックの貼り付け読み込み（簡易版）を入れる**：サンプルパックの動画 ID は仮のものなので、そのままでは音が出ない。M1 で本物のパックを1つ貼り付けて試せるようにする。行番号つきのエラー表示などの仕上げは M6 のまま
- **M3 にタブバーを入れる**：画面が2つ以上になるのが M3 から（M1・M2 はクイズの画面だけ）

## 公開と非公開について

- M1〜M8 の間、本番 URL（`〜.vercel.app`）は誰でも開ける状態になる見込み
  - 【未確認】Vercel の無料プラン（Hobby）のログイン保護（Vercel Authentication）は、プレビューの URL は守るが、本番の URL は守らない見込み。M1 で設定画面を見て確かめる
  - その間、サーバーに載るのはサンプルパック（架空の英文）だけ。本物のパックは、貼り付けた端末のブラウザの中（localStorage）にしかないので、他人には見えない
- M8 でログイン必須にし、パックと記録は Supabase の RLS で本人しか読めないようにする

## M1 の結果と、確かめ方

- 手順は `docs/setup.md`（PR のマージ、Vercel のプロジェクト作成、iPhone での確かめ方、本物のパックで試す方法）
- リポジトリに `main` がなく作業ブランチが既定になっていたので、So の許可を得て Claude が `main` を作った（M1 の時点の内容）。既定のブランチの切り替えは So が GitHub の設定で行う
- Vercel のプロジェクトは、Claude の側（Vercel の接続）からは権限がなく作れなかった（403）。So に画面で作ってもらう
- 自動テスト（Playwright）は、この開発環境から YouTube に接続できないため、**偽の YouTube プレーヤー**（`e2e/fake-youtube.js`）で行っている。区間の頭への移動・終わりでの停止・聞き直しの回数・保存は確かめた
- 【未確認】本物の YouTube での区間再生（iPhone の Safari、止まる位置のずれ、字幕が出ないか）。So に iPhone で確かめてもらう
- 【未確認】Vercel のプレビュー URL のログイン保護が iPhone でどう見えるか

- So が iPhone の Safari で本番 URL を開けることを確かめた（2026-11-20）。存在しない動画 ID（例の `XXXXXXXXXXX`）では、YouTube がエラー 150（埋め込み禁止と同じ番号）を返した。メッセージを「埋め込みが許可されていないか、動画 ID が誤っています」に直し、再生できないときは再生ボタンを隠した
- 【未確認】本物の動画での区間再生（iPhone）

## M4 の結果

- フィードで間違えた問題（惜しいを含む）を復習キューに入れる。復習の画面で、今日が期日の問題を期日の古い順に出す
- 間隔は 1日 → 3日 → 7日 → 14日 → 30日 → 卒業。復習で不正解・惜しいなら1日後に戻る。日付は午前4時で切り替わる
- 復習の聞き直しは無料で何回でも（文・全体）。ヒントは使える。XP は基本点の半分（惜しいは 25、ヒントでさらに半分）
- 復習タブに今日の件数（赤い丸）。復習が終わったらバッジを判定する。パックを削除したら、その問題はキューから外す
- 単体テストで、午前4時の区切り（深夜・月またぎ）と段の進み方を確かめた。画面のテストで、Playwright の時計を「1日目の夜 → 翌日の深夜3時 → 朝5時」と進めて、出る・出ないを確かめた

### M4 で自分で決めたこと

- フィードで正解しても、すでにキューにある問題の段は変えない（段が進むのは復習で正解したときだけ）
- 再挑戦（2回目以降のクリップ）で間違えた問題もキューに入れる
- 復習の画面では、答える前は自動で再生しない（iPhone ではタップしないと音が出ないため）。「🔁 文を聞く」を押して聞く
- 復習の件数は、画面を開いた時刻で数える。アプリを開いたまま午前4時を過ぎても、開き直すまで件数は増えない
- 復習では、どの回の解答か（`sessionId`）を付けない（クリップ1本を解いた回ではないため）

## M6 の結果

- 設定タブ：ファイルからの読み込み（「📄 ファイルを選ぶ」）と貼り付け。ファイルの中身はテキスト欄に出す
- エラーに行番号を付ける。JSON の書き方の誤り（カンマ抜け・余分なカンマ・' や “ ” の引用符・閉じていない文字列など）は自前の読み取り（`json-locate.ts`）で行・列と日本語の説明を出す。中身の誤りは、その値の行（足りない項目は、それを持つべきオブジェクトの行）。「行へ移動」でテキスト欄のその行を選ぶ
- 同じ packId：新しい版はそのまま置き換え（「版 1 → 2 に置き換えました」）、同じ版・古い版は確認してから置き換える。置き換えで消えた問題は復習キューから外す
- パック一覧に問題数を出す。データの大きさの表示、データの書き出し（JSON ファイル）、すべてのデータの削除（2回押し）
- 画面のテストで、ファイルの読み込み・行番号と行への移動・カンマ抜け・置き換えの確認・書き出し・全削除を確かめた。あわせて、記録の画面の横棒を PC でクリックすると内訳が消える不具合を直した

## M8 の結果

- 作業記録アプリと同じ Supabase プロジェクトに、`ls_` で始まる表を5つ作った（So の選択）。Claude が Supabase の接続からマイグレーションを適用し、RLS・未ログインの権限・Realtime を確かめた。セキュリティ診断で `ls_` の表への指摘はなし
- ログインはメールとパスワード（So の選択）。Supabase の接続情報（Vercel の環境変数）が入っていればログイン必須、入っていなければ今までどおりブラウザ内保存で動く

- ログイン後に一度だけ「このブラウザの記録を取り込むか」を聞く（サーバーの読み込みが終わってから）。同じ ID はサーバー側を優先、バッジは合わせる
- 設定タブに「アカウント」（メールアドレス・同期の状態・読み直す・ログアウト）
- テスト：DB（一時的な PostgreSQL 16 で RLS と制約。わざと壊して失敗することも確認）、単体（行の変換・差分・取り込み、偽の Supabase クライアントでのストア）、画面（偽の Supabase につなぐ別のビルドで、ログイン・取り込み・保存・別の端末・エラーからの回復・ログアウト）
- 【未確認】本物の Supabase でのログインと同期、Realtime での別の端末への反映、iPhone のホーム画面のアプリでのログイン

### M8 で自分で決めたこと

- 主キーは (user_id, id)。パックの ID はユーザーごとに一意で、ほかの人と同じ ID になりうるため。送る行には user_id を付ける（RLS で本人以外は拒否）
- 進み具合（コンボ・バッジ・フィードの絞り込み）は `ls_progress` の1行にまとめる。フィードの絞り込みも端末間で同じにする
- 取り込みのあとも、ブラウザ内のデータは消さない（控えとして残す）
- ログイン中の「すべてのデータを削除」は、サーバーのデータも消す（ボタンにその旨を出す）
